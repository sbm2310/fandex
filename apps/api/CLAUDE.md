# Fandex API — notes for Claude

Loaded when working in `apps/api`. Project overview, rules and roadmap: the root [CLAUDE.md](../../CLAUDE.md). Add new API gotchas here.

- **API (NestJS 12):** ESM project (`"type": "module"`, `module: nodenext`), so relative imports in `apps/api` need `.js` extensions (`./app.module.js`). Config is validated with a zod schema (`src/config/env.ts`) via `ConfigModule.forRoot({ validationSchema })`. Shared app setup lives in `setup-app.ts` so e2e tests use the same configuration as `main.ts`. OpenAPI docs at `/docs`.
- **Local database:** `npm run db:up` / `db:down` (Docker Compose, Postgres 18; dev-only credentials in `docker-compose.yml`). Requires Docker Desktop running. Copy `apps/api/.env.example` to `apps/api/.env`.
- **Prisma 7.10 (pinned stable):** npm's `latest` tag for the `prisma` CLI pointed at an 8.0 _release candidate_ (2026-10-05); don't upgrade to 8 until it's final. Prisma 7 specifics: connection URL lives in `apps/api/prisma.config.ts` (not the schema), the client is generated into `src/generated/prisma` (gitignored; `prisma generate` runs automatically before build/dev/typecheck/test), it connects via `@prisma/adapter-pg`, and `migrate dev` no longer runs `generate`. Schema changes: edit `prisma/schema.prisma`, then `npm run db:migrate -w @fandex/api -- --name <change>` and commit the migration.
- **Auth (Better Auth 1.7 via `@thallesp/nestjs-better-auth`):** routes under `/api/auth/*` (`sign-up/email`, `sign-in/email`, `sign-out`, `get-session`…). A **global guard protects every route**; mark public ones with `@AllowAnonymous()` and read the user with `@Session() session: UserSession`. Apps must be created with `appOptions` (`bodyParser: false`) from `setup-app.ts`. Gotchas found in Task 3: (1) with `generateId: 'uuid'` Better Auth sends **no** id, so auth models need `@default(uuid(7))`; (2) Better Auth **disables its origin/CSRF check when NODE_ENV=test** — we set `advanced.disableOriginCheck: false` so tests exercise production security; (3) its rate limiter (3 failed sign-ins → 429) is off in tests only. To see the tables Better Auth expects after an upgrade: `npx auth@<version> generate` against a throwaway config, then port the fields into `schema.prisma` with our snake_case mappings.
- **Catalog API** (`GET /catalog/search?q=`, `GET /catalog/isbn/:isbn`, public): results are upserted into `catalog_item` (stable ids, shared by all users); ISBN lookups are served from the DB for 30 days (stale copy returned if Open Library is down); searches are cached in memory for 1 h (per process). All Open Library calls go through `RateLimitedCatalog` (≥350 ms apart, under the 3 req/s identified limit). `CatalogError` → 502, rate-limited → 503. Params are validated with zod via NestJS 12's `@Query('q', { schema })` + global `StandardSchemaValidationPipe({ transform: true })`. Tests replace the source with `overrideProvider(BOOK_CATALOG)`.
- **Collection API** (`GET/POST/DELETE /collection`, signed in): every query is scoped by `session.user.id` (never a request field); another user's item answers **404, not 403** (doesn't reveal it exists); `POST` is idempotent (201 new / 200 existing, safe under concurrent double taps via the unique `(user_id, catalog_item_id)` constraint); items cascade-delete with the user; catalog entries can't be deleted while owned. Isolation tests were mutation-checked (removing the user filter makes them fail). CSRF: our own routes rely on Better Auth's SameSite=Lax session cookie + JSON bodies + CORS limited to trusted origins.
- **Tests are hermetic:** `ConfigModule` ignores `.env` when `NODE_ENV=test` (found in Task 9: a test silently used the developer's real Rebrickable key). The e2e env in `vitest.config.e2e.ts` provides every variable.
- **Deployment (Render free + Neon free; `render.yaml`):** one Render web service runs the API **and serves the exported web app** (`WEB_APP_DIR`, SPA fallback in `src/web-app.ts`) from the same origin, so the web session cookie is first-party. All API routes are under **`/api`** (`setGlobalPrefix`; docs at `/api/docs`, health at `/api/health`); the app's `apiFetch` adds the prefix. Build: `npm ci --include=dev && npm run build:deploy`; start: `npm run start:deploy` (runs `prisma migrate deploy` first — Render's pre-deploy command is paid). `BETTER_AUTH_SECRET` is generated by Render; `BETTER_AUTH_URL` defaults to Render's `RENDER_EXTERNAL_URL`, and the API's own origin is always trusted. `TRUSTED_ORIGINS` includes `exp://**` while the iPhone app runs in Expo Go. **Never add a payment method to the Render workspace** (without one, Render suspends rather than bills). Email (verification/password reset) is deferred: free providers need a domain we don't own. Rate limiting relies on Render's `X-Forwarded-For` (not tamper-proof; acceptable for now). Gotchas from the first deploy: a Blueprint **drops `sync: false` variables left empty** (add them later under Environment → Edit); `DATABASE_URL` must be Neon's plain **Connection string** with pooling off — a `psql '…'` or `DATABASE_URL=…` snippet fails with Prisma `P1013` ("scheme is not recognized"). Neon free: 0.5 GB per branch. The Render and Neon MCP connectors give read access to deploys, logs and the database.
- **Universes in the API** (Stage 3 Task 3): tables `universe`, `character`, `catalog_item_universe`, `catalog_item_character` (automatic links, cascade), `sync_state`. `UniverseSeedService` (in `onModuleInit`, so before requests) syncs the seed when `seedHash()` (seed + `UNIVERSE_MATCHER_VERSION`) changes: upserts by slug (ids stay stable), deletes universes/characters the seed dropped, then `UniverseLinker.relinkAll()`. **Bump `UNIVERSE_MATCHER_VERSION` in core when matching rules change.** Links are rewritten on every catalog upsert (`CatalogService.save`) and signals refresh; responses load them with `linksInclude`/`linksFromRow` (seed order). Contract: `universes: string[]`, `characters: {universe, character}[]` on catalog items, both `.default([])` so older payloads still parse. Public `GET /universes`, `GET /universes/:slug` (parsed through the zod schemas so no internal fields leak). `resetDatabase` keeps `universe`, `character`, `sync_state` (reference data); tests that change them must restore them.
- **Collection by universe** (Stage 3 Task 4): `GET /collection/universes` (signed in) returns the universes the user owns items from — `itemCount`, `categoryCounts` (only non-zero), up to 4 newest `coverUrls`, and characters with counts — computed by core's pure `summarizeCollectionUniverses(items, directory)`, which the app reuses for guest mode (the seed itself works as the directory). Crossovers count in each universe. Today the links are the automatic ones; Task 7's manual fixes will apply on top.
- **AI in the API** (Stage 4 Task 2): `AiModule` — `ChatClient` (`src/ai/chat-client.ts`, any OpenAI-compatible provider; `ChatModel` interface behind the `CHAT_MODEL` token, null without `GROQ_API_KEY` → AI endpoints 503, like LEGO without a key), `ShelfReader` (core's prompt, parser and `SHELF_READING_SETTINGS`), `AiQuotaService` (table `ai_usage (user_id, day DATE, kind)`, UTC days; checked before the request, **counted only after success**, so provider failures cost nothing; per-user limit → 429, everyone's daily limit → 503). `POST /api/ai/shelf-scans` is **multipart** (`images`, 1–3 JPEGs ≤ 2 MB, checked by magic bytes; `FilesInterceptor` with memory storage) because the auth module's global JSON parser keeps Express's 100 KB limit; provider 429 → our 503 with the provider's `Retry-After`, other failures → 503 with `Retry-After: 30`. `GET /api/ai/quota` → `{ available, shelfScans: { used, limit } }`. Contracts in core (`contracts/ai.ts`). Settings: `AI_BASE_URL`, `AI_VISION_MODEL`, `AI_SHELF_SCANS_PER_USER` (5), `AI_SHELF_SCANS_PER_DAY` (30; each scan reads the photo twice). e2e tests override `CHAT_MODEL` with a fake; quota isolation, the global limit and "not charged on failure" were mutation-checked.
- **AI providers** (`apps/api/src/ai/ai-providers.ts`): `AI_PROVIDER` = `groq` (default; two readings a scan), `gemini-free` (free tier, one reading, `reasoningEffort: 'none'`, key `GEMINI_API_KEY`) or `gemini` (paid/prepaid: same, no training on inputs). Each preset has the endpoint, model, readings per scan and whether the provider may train on photos; `AI_BASE_URL` / `AI_VISION_MODEL` override. `GET /api/ai/quota` returns `provider: { name, usesPhotosForTraining }` and the scan screen's privacy note follows it. **Production uses `gemini-free` since 2026-10-08** (owner testing alone; limits set to 20 a day on Render): on the app's settings Gemini found 49/52 items with 94% of readings real vs Groq's 22/52 and 41%. The free tier allows 20 requests a day for everyone and may train on photos, so before other users: prepaid `gemini` ($5 ≈ 700 scans at ~0.7¢), or back to `groq`. **Fallback:** when the shelf provider isn't Groq and fails (timeout, 5xx, 429, network), `ShelfReader` reads the photo with Groq instead (`SHELF_FALLBACK_MODEL`, null without a Groq key or when Groq is the provider); found when a real Gemini scan timed out on 2026-10-11. The quota response's `provider.fallbackName` makes the privacy note say so.
- **Ask in the API** (Stage 4 Task 7): `POST /api/ai/ask { question }` (signed in, ≤ 300 chars) → `{ query, answer, itemIds, unknown, method: 'ai' | 'keywords', notice?, quota }` (core `askResponseSchema`). `QuestionAnswerer` (`src/ai/question-answerer.service.ts`) sends core's `askPrompt` (question, today, universe ids/names — **never the collection**) to the `ASK_MODEL` provider (`AI_ASK_PROVIDER`, default `groq`; its own token, so shelf scans can stay on Gemini) with a strict JSON schema (`modelQueryJsonSchema`; `ChatRequest.jsonSchema` → `response_format`), temperature 0, 400 reply tokens; core's `resolveModelQuery` validates the reply and maps character names ("Batman") to seed slugs (a name in two universes stays unresolved unless a named universe settles it). It then runs `runCollectionQuery` over `CollectionService.queryable(userId)` (rows → `QueryableItem`, user's category and links). **Always answers:** no model, the user's or everyone's allowance reached (`AiQuotaService.check`), a provider error or an unusable reply → `parseQuestionLocally` with a `notice`, and only AI answers are counted (`AI_QUESTIONS_PER_USER` 30, `AI_QUESTIONS_PER_DAY` 100; usage kind `question`). `GET /api/ai/quota` also returns `questions`. Real replies for 12 questions (roadmap ones, an injection attempt) are recorded with `npx tsx eval/record-ask.ts` into `packages/core/src/ask/__fixtures__/ask-replies.json` — re-record when the prompt or model changes. Known gap: author names in Hebrew normalize to nothing, so "books by Tolkien" misses Hebrew editions.
- **Pre-orders in the API** (Stage 5 Task 3, `src/preorders/`): tables `preorder` (user cascade; `catalog_item` FK `NO ACTION` like the collection's; money ints + `currency` CHAR(3); `release_date` DATE + `release_precision`; store, order number/link, notes; `arrived_at`) and `preorder_date_change` (from/to date + precision, `source` user | openlibrary). `GET/POST /api/preorders`, `GET/PATCH/DELETE /api/preorders/:id`, `POST /api/preorders/:id/arrive`. Scoped by user (others' → 404, mutation-checked); someone else's figure can't be pre-ordered. The **first expected date is recorded as history** (from null) so "originally" works; a PATCH records a change only when the date or precision actually differs (mutation-checked); paid ≤ price is re-checked against stored values (lowering the price below what's paid → 400). **Arrive** reuses `CollectionService.add` (idempotent, ownership, LEGO minifig refresh), then closes the pre-order; repeating returns the same item; a cancelled one → 409; an arrived one's status can't change (409). **Deleting** a pre-order also deletes a figure created only for it (not owned, not on another pre-order); removing a figure from the collection keeps it while a pre-order refers to it (mutation-checked). The controller takes core's `CreatePreorderInput`/`UpdatePreorderInput` (the schemas' parsed output).
- **Book release dates from Open Library** (Stage 5 Task 6; spike results in the plan): editions' `publish_date` (free text: "Nov 10th 2026", "28.06.2027", "2027"…) is parsed by core's `parseOpenLibraryDate` (as precise as the text allows; ambiguous "01/12/2027" → year only; non-English month names → year) into `CatalogBook.publishDate` / contract `publishDate`, stored in `catalog_item.publish_date` + `publish_precision`. The app's `PreorderLink` passes it as `release`/`releasePrecision` route params when its period hasn't ended, and the form starts with it ("From Open Library…"). A pre-order **follows the catalog's date** (`preorder.follows_catalog_date`, in responses as `followsCatalogDate`) when its date equals the catalog item's at creation or after the user's change (both none counts, so a later Open Library date fills it in); a user's different date stops following. `GET /preorders` first re-asks Open Library (`CatalogService.refreshEdition`, `edition_key:` search through the rate-limited catalog) about open, following book pre-orders not fetched for 24 h — at most 5 per listing within 4 s, failures logged and retried next time — then moves following pre-orders with core's `followCatalogDate` (ignores a vaguer date for the same time: "2027" after "March 2, 2027") and records the move with `source: openlibrary`. The move is a guarded `updateMany` (same old date) in a transaction, so simultaneous listings record it once (mutation-checked with a test that holds Open Library's answer until all three requests ask). Date helpers shared by both services: `src/common/days.ts`.
- **CORS is ours, not the auth module's** (found in Stage 5 Task 4): `@thallesp/nestjs-better-auth` enables CORS with methods `GET, POST, PUT, DELETE` only, so a PATCH from the web app on another origin (local dev: 8081 → 3000) failed in the preflight's wake — editing items or pre-orders. `AuthModule` now has `disableTrustedOriginsCors: true` and `setup-app.ts` calls `enableCors` with the same `trustedOrigins(env)` (exported from `auth/auth.ts`, also used for Better Auth's CSRF check) plus PATCH; a test checks the preflight. Production serves the web app from the API's origin, so it wasn't affected.
- **Deadlocks under parallel searches** (found by a real shelf scan): ~13 simultaneous searches each saving ~20 overlapping books made Postgres abort link transactions (`P2034`, "deadlock detected"), and the affected search returned nothing. `CatalogService.search` now saves results one at a time and `UniverseLinker.link` retries a deadlock victim up to 3 times; the e2e test reproduces it (it fails intermittently without the retry — run it several times when touching this). Core's parser also strips a leading publisher ("MARVEL: PLANET HULK"), which the model sometimes adds.
- **API e2e tests** use a separate `fandex_test` database: `test/global-setup.ts` creates it and runs `prisma migrate deploy`; files run sequentially; `resetDatabase()` truncates tables between tests. CI provides Postgres as a service container.
- **Series in the API** (Stage 6 Task 3, `src/series/`): tables `series` (Wikidata id, name, `entries`/`extras` as JSON validated with core's `bookSeriesSchema` on read) and `work_series` (work key → series id or null = none, `checked_at`). `GET /api/series/works?keys=` (public, ≤ 50 `OL…W` ids, core `workKeysQuerySchema`) answers from the database and asks Wikidata (`SERIES_SOURCE`, spaced 1 s) only for works unknown or checked over 30 days ago, one at a time within an **8 s budget**; a fetched series records **every** member work, so several owned books of a series cost one query. Wikidata down → cached answer (stale is fine) or null ("not known yet", asked next time); 429 → stop asking in that request; budget out → logged. Real Wikidata: 0.7–3.6 s a query, occasionally slower (one first call ran out of budget and answered null, then filled in). `GET /api/catalog/work/:workKey` (`workKeyParamSchema`) = `CatalogService.search("key:/works/…")` (same cache and spacing) → the edition for that work, saved like any result; 404 if none. e2e tests override `SERIES_SOURCE` with a fake; the "covered" skip, the 429 stop and the 30-day re-check were mutation-checked.
- **"Not known yet" vs "no series"** (Stage 6 Task 8): `GET /series/works` marks a work `pending: true` when it was neither cached nor answered in that request (Wikidata slow/busy); `SeriesCatalog.seriesForWorks` returns `{ series, pending }`, and `useBookSeries` / `useSeriesOverview` use `refetchInterval` 20 s while anything is pending (otherwise the null would be cached for an hour). Stage 6 went live with Stage 7 on 2026-10-15.
- **Shared figures in the API** (Stage 7 Task 3): `catalog_item.source = fandex` rows come from `FigureSeedService` (`src/catalog/figure-seed.service.ts`; list injected as `FIGURE_SEED_ENTRIES`, sync marker `sync_state` `figure-seed`) — never insert them by hand. Ownership logic still keys on `owner_id` (null = shared), so shared figures work everywhere catalog items do. **Curated links** travel as `matchSignals.curated` and bypass matching; use that for any item whose links a person chose. `kind=figures` search is in-process over all shared figures (fine for thousands; revisit with an index if the catalog grows far beyond). In e2e tests the figure sync doesn't run on startup: call `app.get(FigureSeedService).sync()` after `resetDatabase` (override `FIGURE_SEED_ENTRIES` with a small fixture unless the test is about the real list).
- **Figure suggestions** (Stage 7 Task 5, `apps/api/src/figure-suggestions/`): approved figures become `source = fandex` with no owner — "shared" means `fandex`, whether curated or approved; `FigureSeedService` only removes dropped rows with **no** suggestion. Merge order matters: detach the suggestion (`catalogItemId: null`) before deleting the private copy, or the cascade deletes the suggestion. `AdminService` (`src/admin/`) reads `ADMIN_EMAILS` (e2e: `admin@example.com` in `vitest.config.e2e.ts`; Render: `sync: false`). **The app's current user comes from Better Auth's session, so `isAdmin` is always false there**; the app asks `GET /me` instead (`useIsAdmin()` in `hooks/use-admin.ts`, Stage 7 Task 6). The admin screen is `app/admin/suggestions.tsx`, linked from the Account tab for admins only; `AdminReviews` service with fake `createFakeAdminReviews`. Tests that mock `confirm` must `mockReset()` it in `beforeEach` (call counts carry over). App: `figureSuggestions` service (`ApiFigureSuggestions`; fake `createFakeFigureSuggestions(initial)`), `hooks/use-figure-suggestions.ts` (`useSuggestionFor(figure)` finds by `catalogItemId` or `mergedIntoId`), `components/figure-suggestion.tsx`. In supertest, build requests lazily (`() => agent.get(…)`): creating several before awaiting fails ("reading 'address'").
- **Box scanning** (Stage 7 Task 8): `POST /api/ai/figure-scans` → `FigureScanService` (`apps/api/src/ai/`), allowance kind `figure_scan` with its own limits; `ShelfReader.readBox` shares `withFallback` with shelf reading. App: `app/figure-scan.tsx`, `FigureScanner` (`services/figure-scanner.ts`, errors are `ShelfScanError`s via the exported `failure()`), `useFigureScan` (merges `figureScans` into the cached quota, key `aiQuotaKey`). "Add it by hand" from a scan navigates to `/add?kind=figures&byHand=1&title=…&scan=<now>`; the Add tab keys `AddFigureForm` on `scan` so a new scan remounts it with `initial`. Photo picking/privacy text: `utils/scan-photo.ts`.
- **Display names and passwords** (account page Task 1): Better Auth's own `/api/auth/update-user` and `/api/auth/change-password` (`revokeOtherSessions` keeps the current session). Better Auth stores any name, so a `hooks.before` middleware (`checkDisplayName` in `auth/auth.ts`) checks sign-up and rename names with core's `displayNameSchema` (trimmed, 1–50) → 400 `INVALID_NAME`, and passes the trimmed name on (mutation-checked). Pass `hooks` as a `BetterAuthOptions['hooks']` variable: inline, `createAuth`'s inferred type names Better Auth internals and `tsc` fails with TS2883.
