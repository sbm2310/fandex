# More universes plan

**Goal:** Fandex knows five universes (Middle-earth, Star Wars, Wizarding World, DC, Marvel). Items from any other franchise sit in the collection unlinked: no universe page, no characters, nothing for Ask to find. This plan adds six more, chosen by the owner on 2026-10-29, through the same curated seed and matcher, without false links.

**Demo at the end:** a collection with A Game of Thrones, The Way of Kings, One Piece vol. 1, a Pokémon guide, a LEGO Jurassic World set and a Toy Story book shows six new universe cards in their own colours, each with its characters ("Tyrion Lannister, 1 item"); "What Pokémon stuff do I own?" answers; books about sand dunes, swimwear or dinosaurs in general stay unlinked.

## Decisions

| Question                | Decision                                                                                                                                                                                                                                        | Why                                                                                                         |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Where the data lives    | **The existing seed** (`packages/core/src/universes/universe-seed.ts`), same fields as today; no schema change                                                                                                                                  | Growing Fandex to a universe is a data change by design; the API syncs the seed on start                    |
| Sources                 | **Wikidata** (CC0) for ids, names and the character list (ranked by how many Wikipedias cover them, as for the first five), **Rebrickable themes** from the recorded fixture; aliases, places and guards written and reviewed by hand           | Same sources and terms as Stage 3; no new data source                                                       |
| Characters per universe | **15–25 main characters**                                                                                                                                                                                                                       | Like the first five; enough for "N of M characters" to mean something                                       |
| Wikidata ids            | **Every id checked by a script** against Wikidata's English label before commit                                                                                                                                                                 | Stage 3 found a guessed id that was a volleyball player                                                     |
| Disney & Pixar          | **One universe** for Disney and Pixar animation. **Never** matched on the word "Disney" alone or a publisher: Disney Press and Disney Lucasfilm Press publish Star Wars and Marvel books, and Disney owns both                                  | The owner chose it as one; splitting by film franchise (Toy Story, Frozen) is a later option                |
| Generic words           | **Never** a universe signal: "dune", "dinosaur(s)", "one piece" in sewing or swimwear subjects, "princess", "cars", "ice and fire" alone; "Ash", "Link", "Nemo", "Belle", "Anna", "Ariel", "Hoid" style names are `ambiguous` or full-name only | The matcher's existing guards (ambiguous names, no single-word aliases, `excludePhrases`) cover these       |
| Matching rules          | **Unchanged** unless a batch proves a new rule is needed; then bump `UNIVERSE_MATCHER_VERSION`                                                                                                                                                  | The seed hash already changes with the seed, so the API relinks every catalog item on deploy anyway         |
| Colours                 | **One colour set per universe** in `apps/mobile/src/constants/universe-colors.ts`, dark and light, same contrast rule as today (accent ~4:1 on ground, bars and large text only)                                                                | Unknown slugs already fall back to neutral, so each batch can add its own                                   |
| Figures                 | **Out of scope.** The curated figure list stays Star Wars / Marvel / DC Hot Toys and InArt; new universes make Jurassic Park or Disney figures possible later                                                                                   | Figures need their own sourcing (Stage 7 rules)                                                             |
| Cost                    | **$0**                                                                                                                                                                                                                                          | Wikidata and the recorded fixtures; recording real responses uses the owner's existing Rebrickable key once |

## Tasks (each leaves the app working)

**1. Tooling: verify, record, compare.** ✅ No seed changes yet.

- `apps/api/eval/verify-universe-seed.ts`: fetches the English label of every universe and character Wikidata id (one `wbgetentities` request per 50 ids, a descriptive User-Agent, as for series) and prints any whose label doesn't match the seed's name or an alias. Run it on today's seed: it must pass.
- `apps/api/eval/record-signals.ts`: records real match signals for a list of sample items (Open Library editions by key, Rebrickable sets by number, through the existing adapters) into `packages/core/src/universes/__fixtures__/signals.json`, keeping existing entries. Today's file was recorded by hand-run calls; this makes adding samples repeatable. Rebrickable needs `REBRICKABLE_API_KEY`; requests are spaced as in production.
- `apps/api/eval/universe-diff.ts`: runs `matchUniverses` with the current seed and a candidate seed over every `catalog_item` in the **local** database and prints items whose links change. The review step of each batch: new links should all be right, and existing links must not move.
- _Demo:_ the three scripts run; the verify script passes on today's seed.
- _Done (2026-10-29):_ npm scripts `eval:verify-seed`, `eval:record-signals` (samples in `apps/api/eval/signal-samples.json`) and `eval:universe-diff` in `apps/api` (each builds core first). ## How to work

- **One task per session or commit**, in order; each leaves every check passing (`npm test`, `npm run typecheck`, `npm run lint`, `npm run format:check`).
- **Data comes from Wikidata and recorded real responses**, never from memory: run the verify script before committing seed changes, and add recorded signals (positives and negatives) for every universe.
- **Review the diff report** (`universe-diff.ts`) for every batch against the local catalog, and say in the commit what changed.
- Tests never call the network; the eval scripts do, and never run in CI. Put scripts in `apps/api/eval/` (a file under `apps/api/src/` restarts the dev API).
- Restart the `api` dev server after rebuilding core.
- Read `packages/core/CLAUDE.md` (universe matching, its guards) before changing the seed.

## Risks

- **False links** are the main risk: generic words ("dune", "dinosaurs", "one piece", "cars", "princess"), Disney as a publisher or owner of Star Wars and Marvel, Conan Doyle's The Lost World, Captain Nemo. Each gets a guard and a recorded negative.
- **Open Library's data is patchy:** subjects are merged across a work's editions (a reason The Hobbit carries "Graphic novels"), some volumes list no characters, Hebrew editions normalize to nothing. Recorded signals show what the matcher really sees.
- **Relinking on deploy** touches every catalog item: fine at today's size; check it on Render's free instance and note the time.
- **Disney & Pixar is broad** (hundreds of characters): keep to 25 well-known ones; a later split by film franchise stays possible because links are stored by slug.
- **Pokémon "characters"** are mostly species: list the best-known Pokémon and trainers, and check Ask's character answers read naturally ("2 Pikachu items").
- **LEGO themes 775 and 776 are new:** Rebrickable may have few sets in them yet.
